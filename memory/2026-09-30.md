## Decisions

For replacement AI work, compared dropping requests, polling/retry, reusing a mismatched cached answer, a separate unstructured worker queue, and per-feature suspension within the original task. Chose per-feature suspension plus screen request ownership: preserves structured cancellation and uses no dependency or new module. The strongest rejected alternative was cancelling/restarting a shared worker: it transfers model work ownership and complicates cancellation.

For wheelchair history, retained the existing bucketed aggregator and added a captured quantity selection instead of querying hundreds of days through separate daily-summary operations. For numeric model/fallback data, enforce existing declared bounds before publishing or converting instead of trusting generation guides or treating a corrupted target as a usable workout.

For HealthKit transitions, compared task cancellation, a new generation token and rechecking the existing saved preference at admission boundaries. Chose the preference check: noncooperative reads may ignore cancellation, and disabling sync does not promise to erase retained data or invalidate an operation that completes after reenabling. For screenshot packaging, stage all copies/conversions before replacing output; a transactional directory swap would broaden the existing mixed-output ownership contract.

Updated Wrangler through pnpm to 4.144.0, resolving the audit's transitive undici advisories; frozen lockfile install and full development audit passed. Sources used for decisions: [Swift actor reentrancy](https://www.swift.org/migration/documentation/swift-6-concurrency-migration-guide/dataracesafety/), [Apple actor invariants across suspension](https://developer.apple.com/videos/play/wwdc2021/10133/), and [undici advisory](https://github.com/advisories/GHSA-rfgv-xxqx-mfg5).
